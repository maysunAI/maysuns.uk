A Day With T00

A composite scenario built from how a workday like this actually goes — not one specific client, but every step here maps to a real feature (the site's own product-generator, PJ14's email agent, T00's req/reply log). The "client" is illustrative.

☕

Morning: today's list

Coffee in hand, I ask T00 out loud: "What's on today?" I haven't opened a single file, but T00 already knows — unread emails, a project deadline, a doc I left half-finished yesterday. A few seconds later, a prioritized to-do list comes back.

📧

A new request, buried in the list

One item doesn't look familiar: a client email asking for a landing page, plus a meeting. T00 had already read the email and turned it into a task — before I'd even opened my inbox.

✨

Built in one shot

"Go ahead and build it." A few minutes later, the landing page is live — design, copy, layout, all done. No starting from a blank file.

🤝

Off to the meeting

I walk in with the live page already up on my phone. Showing something real beats describing it. Specific notes come back — "make this stand out," "this line reads too stiff."

📱

An email on the way back

On the train home, I email T00 the notes straight from my phone. No laptop required.

✅

Already fixed by the time I check

T00's reply is waiting with a link to the updated page — done while I was still commuting.

🔍

Back home: polishing the details

This is where T00's req/reply log actually earns its keep. This morning's conversation, the client's in-person feedback, the email sent from the train — it's all one continuous record. I can trace exactly what changed and why, and refine the details without losing the thread.

📤

Sign-off

Final version goes to the client: "Here's the update."

📄

Two write-ups

One last thing: "Write it up." Two documents come back — a short "how to use this page" guide for the client, and a personal note on how the job went, for next time.

🎉

Done

Today's list is one item shorter.

⚠️ Illustrative scenario: the client and meeting are a composite example, not a specific real engagement. Every capability shown is real — this site's own AI app generator, PJ14's email-driven agent, and T00's req/reply log.

How I Work With AI: 3 Rules You Can Steal

I've been building with tools like Claude Code for months and picked up a few collaboration habits worth sharing — no project specifics, just how I work with AI itself.

1. Keep substantive answers in one file, not scattered across chat. I have the AI write every real answer into a persistent reply log and keep the terminal output to a one-line confirmation — the log stays a complete, searchable record as conversations get longer.

2. Label trust levels in code instead of relying on memory. Tags like trust: high/medium/low tell the AI "safe to change freely" versus "check with me first," so I don't repeat instructions every time.

3. Force a clear line between "actually done" and "placeholder." Progress reports must separate what's genuinely working from what's stubbed out — this habit has saved me from more than one "I thought this was finished" surprise.

None of this needs special tooling — just communication habits. Anyone working with AI day to day can copy them directly.
